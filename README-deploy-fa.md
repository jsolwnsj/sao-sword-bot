# دانلودر تلگرام — اینستاگرام + تیک‌تاک + یوتیوب + پورن‌هاب + ساندکلود + پینترست + اسپاتیفای

ربات تلگرام با پایتون که لینک اینستاگرام (ریلز/پست عمومی)، تیک‌تاک،
یوتیوب، پورن‌هاب، ساندکلود، پینترست و اسپاتیفای را می‌گیرد و همان‌جا
توی همان چت برمی‌گرداند. هم توی پی‌وی کار می‌کند، هم توی گروه.

## چی داره

- `/start` و `/help` کوتاه، به فارسی
- تشخیص لینک `instagram.com`، `pornhub.com` / `www.pornhub.com`،
  `tiktok.com` (شامل `vm.tiktok.com` و `vt.tiktok.com`)،
  `youtube.com` / `youtu.be` (شامل Shorts و موزیک)، `soundcloud.com`
  (شامل `on.soundcloud.com`)، `pinterest.com` (همه دامنه‌های منطقه‌ای،
  مثل `fr.pinterest.com`) / `pin.it` (لینک کوتاه، خودکار باز می‌شود)
  و `open.spotify.com` / `spotify.com` / `spotify.link` (لینک کوتاه،
  خودکار باز می‌شود)
- اینستاگرام و تیک‌تاک: دانلود مستقیم و ارسال ویدیو/عکس؛ کپشن فقط
  آیدی ربات + قلب (مثلاً `@mybot ❤️`)؛ تیک‌تاک بدون واترمارک
  می‌آید وقتی yt-dlp استریم بدون واترمارک را بدهد، و اسلایدشوی
  عکس تیک‌تاک به‌عنوان عکس فرستاده می‌شود
- یوتیوب: مثل پورن‌هاب — اول منوی انتخاب کیفیت (1080p / 720p /
  480p / 360p) به‌علاوه گزینه «🎵 صوتی (mp3)»، بعد دانلود با عکس
  کاور و نوار پیشرفت که هر ۵ ثانیه ویرایش می‌شود؛ ویدیو با همان
  کاور به‌عنوان thumbnail فرستاده می‌شود؛ گزینه صوتی، بهترین صدا
  را به mp3 تبدیل می‌کند و با عنوان ویدیو می‌فرستد. یوتیوب با
  وب‌سرویس GFw دانلود می‌شود (نه yt-dlp — یوتیوب IP سرور را با
  yt-dlp کامل بلاک کرده بود): وب‌سرویس لینک مستقیم ویدیو و صدا
  را می‌دهد و ربات ویدیو را با بهترین صدا میکس می‌کند
  (ffmpeg -c copy، بدون ریکد) تا ویدیو بی‌صدا نیاید؛ اگر دانلود
  صدا یا میکس نشد، خطا برمی‌گردد و ویدیوی بی‌صدا فرستاده
  نمی‌شود. Shorts هم پشتیبانی می‌شود. کلید وب‌سرویس را توی
  Variables ریل‌وی به اسم `GFWDEV_API_KEY` بگذار؛ بدون آن یوتیوب
  کار نمی‌کند. ویدیوی با محدودیت سنی یا منطقه‌ای با یک پیام
  کوتاه رد می‌شود.
- ساندکلود: اول کاور آهنگ با اسم آهنگ و خواننده زیرش، بعد فایل
  صوتی mp3 با عنوان و خواننده درست (خواننده از `artist`، بعد
  `creator`، بعد `uploader` می‌آید؛ اگر عنوان «خواننده - آهنگ»
  باشد، درست جدا می‌شود و اسم دو بار تکرار نمی‌شود). اگر لینک
  پلی‌لیست باشد، فقط اولین آهنگ گرفته می‌شود.
- اسپاتیفای: دقیقاً مثل ساندکلود — اول کاور آهنگ با اسم آهنگ و خواننده
  زیرش، بعد فایل صوتی mp3 با عنوان و خواننده درست. صدای اسپاتیفای
  DRM دارد و از خود اسپاتیفای دانلود نمی‌شود؛ اسم آهنگ و خواننده و
  کاور از صفحه embed اسپاتیفای (بدون لاگین) گرفته می‌شود و صدا اول
  از جستجوی موزیک وب‌سرویس GFw می‌آید؛ اگر آن نشد، یوتیوب با GFw
  (کیفیت صوتی) و در آخر yt-dlp مستقیم. اگر لینک آلبوم/پلی‌لیست
  باشد، فقط اولین آهنگ گرفته می‌شود.
- پینترست: دانلود مستقیم، بدون منوی کیفیت؛ کپشن فقط آیدی ربات +
  قلب. پین ویدیویی مثل تیک‌تاک با yt-dlp دانلود می‌شود. پین عکسی
  با کیفیت اصلی (originals) از API بدون لاگین خود پینترست گرفته
  می‌شود — چون اکسترکتور yt-dlp برای پین عکسی خطا می‌دهد و پین
  چندعکسی را نمی‌بیند. پین چندعکسی (۲ تا ۲۰ عکس) همه عکس‌ها را
  با کیفیت اصلی می‌گیرد و به‌صورت یک آلبوم (media group، کپشن
  روی عکس اول) می‌فرستد، نه فقط اولی؛ اگر عکس اصلی heic باشد با
  ffmpeg به jpg تبدیل می‌شود. لینک بورد یا پروفایل پین تکی نیست
  و با پیام خطا رد می‌شود.
- دانلودها در پس‌زمینه اجرا می‌شوند؛ ربات موقع دانلود به دستورهای دیگر جواب می‌دهد. تا ۳ دانلود هم‌زمان؛ دانلود چهارم به بعد توی صف می‌ماند و به کاربر گفته می‌شود «تو صف موندی…». هر دانلود پوشه، پیام و پیشرفت خودش را دارد، پس دانلود پورن‌هاب یک کاربر، دانلود ریلز کاربر دیگر را بلاک نمی‌کند.
- پیام پیشرفت همه فازها را نشان می‌دهد: آماده‌سازی، دانلود، ارسال مستقیم، تقسیم و آپلود — هر کدام با نوار، درصد، سرعت و زمان باقی‌مانده؛ هر ۵ ثانیه در همان پیام ویرایش می‌شود.
- ارسال سریع: ربات اول سعی می‌کند لینک مستقیم mp4 را مستقیم به تلگرام بدهد تا تلگرام خودش فایل را بگیرد (بدون دانلود روی ریل‌وی). لینک پورن‌هاب به IP قفل شده (`ip=…&ipa=1`)، پس تلگرام نمی‌تواند آن را بگیرد و ربات خودکار برمی‌گردد به مسیر دانلود؛ دانلود هم با فرگمنت‌های موازی (۸ تا هم‌زمان) سریع‌تر شده، چون پورن‌هاب هر اتصال را حدود ۵۰۰ کیلوبایت/ثانیه محدود می‌کند.
- سقف سخت تلگرام و مدیریت فایل بزرگ: اول کیفیت پایین می‌آید
  (۷۲۰p، بعد ۴۸۰p، بعد ۳۶۰p). اگر باز هم فایل بالای ۵۰ مگ بود،
  **خود ربات** با Telethon bot client (MTProto با BOT_TOKEN) تا
  ۲ گیگابایت می‌فرستد — فرستنده خود ربات است، نه حساب کاربری؛
  نه تقسیم می‌شود، نه فشرده‌سازی (فشرده‌سازی حذف شده است چون
  خیلی طول می‌کشید). سقف ۵۰ مگ فقط برای Bot API از طریق HTTP
  است؛ MTProto آن را ندارد. تقسیم فقط آخرین راه است و سقف
  ۱۰ قسمت دارد. ارسال با حساب کاربری (سشن Telethon) فقط fallback
  است و فقط اگر `TELETHON_SEND_ENABLED=true` ست شده باشد
  استفاده می‌شود (بخش ۵).
- پیام پیشرفت همه فازها را نشان می‌دهد (آماده‌سازی ⏳، دانلود 📥، ارسال مستقیم 🔗، تقسیم ✂️، آپلود 📤)؛ هر فاز نوار، درصد، سرعت و زمان باقی‌مانده دارد و هر ۵ ثانیه در همان پیام ویرایش می‌شود.
- اگر اینستاگرام دانلود نشد، کوکی‌های اختیاری اینستاگرام (بخش ۷)
  را می‌توان اضافه کرد.
- خطاها به فارسی و کوتاه
- فقط محتوای عمومی. yt-dlp با impersonation مرورگر کروم کار می‌کند
  تا پورن‌هاب درخواست را با 403 رد نکند (بخش ۶). اگر باز هم 403 داد،
  کوکی‌های اختیاری پورن‌هاب (بخش ۶) فقط برای همان ویدیو استفاده
  می‌شوند.

## فایل‌ها

| فایل | چیه |
|---|---|
| `bot.py` | کد اصلی ربات (polling) |
| `requirements.txt` | `python-telegram-bot` ،`yt-dlp` ،`telethon` و `curl-cffi` (برای impersonation مرورگر) |
| `Dockerfile` | پایتون ۳٫۱۱ + ffmpeg |
| `railway.json` | دیپلوی با Dockerfile |
| `start.sh` | اجرای ربات (استفاده نمی‌شود مگر لازم باشد) |

## ۱. ساخت ربات با BotFather

1. توی تلگرام برو به `@BotFather`
2. بزن `/newbot` و اسم و یوزرنیم ربات رو انتخاب کن
3. توکن رو کپی کن — به هیچ‌کس نفرست، فقط توی Railway واردش کن

### برای کار کردن توی گروه (مهم)

1. توی `@BotFather` بزن `/setprivacy`
2. ربات رو انتخاب کن و بزن `Disable`
3. بعد ربات رو به گروه اضافه کن؛ دیگه نیازی نیست ادمین باشه،
   فقط عضو گروه باشه کافیه.

## ۲. پوش به گیت‌هاب

یه ریپوی جدید بساز و محتوای همین پوشه رو توی ریشه ریپو بذار
(`bot.py` ،`requirements.txt` ،`Dockerfile` ،`railway.json`).

## ۳. دیپلوی روی Railway

1. برو به railway.com و با گیت‌هاب لاگین کن.
2. New Project → Deploy from GitHub repo → همون ریپو رو انتخاب کن.
3. Railway خودش Dockerfile رو پیدا می‌کند و بیلد رو شروع می‌کند.
4. توی سرویس، تب Variables، این رو اضافه کن:
   - `BOT_TOKEN` = توکن ربات تلگرامت
   - `GFWDEV_API_KEY` = کلید وب‌سرویس یوتیوب (GFw) — برای دانلود
     یوتیوب لازم است؛ بدون آن ربات برای یوتیوب می‌گوید کلید
     تنظیم نشده. کلید را توی گیت‌هاب نگذار.
   - (اختیاری، برای فایل بزرگ — بخش ۵ را ببین: `TELETHON_API_ID` و
     `TELETHON_API_HASH` را اینجا می‌گذاری؛ سشن را با `get_session.py`
     می‌سازی و رشته‌اش را به اسم `TELETHON_SESSION_STRING` اینجا
     می‌گذاری.)
5. صبر کن دیپلوی تمام بشه؛ توی لاگ باید ببینی:
   `Downloader bot started (polling).`
6. دامین لازم نیست؛ ربات با polling کار می‌کند و نیازی به وب‌هوک نیست.
   اگه قبلاً وب‌هوک روی همین توکن ست بوده، اول
   `deleteWebhook` رو بزن تا polling کار کنه.

## ۴. تست

- توی پی‌وی ربات `/start` رو بزن.
- یه لینک ریلز اینستا یا تیک‌تاک بفرست؛ ویدیو با کپشن آیدی ربات + قلب می‌آید.
- یه لینک ویدیوی یوتیوب یا پورن‌هاب بفرست؛ اول منوی کیفیت می‌آید، یکی را انتخاب کن (یوتیوب گزینه صوتی هم دارد). عکس کاور با نوار پیشرفت می‌آید و هر ۵ ثانیه درصد را نشان می‌دهد؛ ویدیو با همان کاور فرستاده می‌شود.
- یه لینک ساندکلود بفرست؛ اول کاور آهنگ با اسم آهنگ و خواننده می‌آید، بعد فایل صوتی mp3 با همان عنوان و خواننده.
- یه لینک آهنگ اسپاتیفای بفرست؛ دقیقاً مثل ساندکلود — اول کاور با اسم آهنگ و خواننده، بعد فایل صوتی mp3. صدا از وب‌سرویس NestAPI می‌آید (بدون کلید)؛ اگر NestAPI نشد، ربات از جستجوی یوتیوب + صدای GFw استفاده می‌کند.
- ویدیوهای خیلی طولانی ممکنه چند قسمت بیان؛ هر قسمت شماره داره.

## ۵. ارسال فایل بزرگ با MTProto / Telethon — خود ربات تا ۲ گیگابایت

**فایل بزرگ را خود ربات می‌فرستد، نه حساب کاربری.** سقف ۵۰ مگابایت
فقط برای Bot API از طریق HTTP است؛ وقتی ربات با Telethon و
BOT_TOKEN خودش (MTProto) وارد می‌شود، سقف ۲ گیگابایت است و
فرستنده خود ربات است. برای این کار فقط `TELETHON_API_ID` و
`TELETHON_API_HASH` لازم‌اند (بخش ۵٫۱ و ۵٫۴)؛ سشن حساب کاربری
برای ارسال لازم نیست — فقط fallback است. سشن را با `get_session.py`
می‌سازی و توی Variables می‌گذاری (بخش ۵٫۳)؛ دستور `/makesession`
حذف شده است.

> ⚠️ ارسال با **حساب کاربری** پیش‌فرض **خاموش** است — ویدیوها
> با خود ربات (Bot API برای فایل کوچک، Telethon bot client برای
> فایل بزرگ) فرستاده می‌شوند. اگر می‌خواهی فایل بزرگ با حساب
> کاربری هم فرستاده شود (fallback)، علاوه بر بخش‌های زیر، متغیر
> `TELETHON_SEND_ENABLED=true` را هم توی Variables ریل‌وی اضافه
> کن. بدون آن، اگر bot client نشد، ربات فایل بزرگ را تقسیم
> می‌کند (سقف ۱۰ قسمت) و با Bot API می‌فرستد.

سقف ۵۰ مگابایت فقط برای ربات‌هاست (Bot API از طریق HTTP). با
MTProto می‌شود تا ۲ گیگابایت فرستاد — چه با حساب کاربری، چه با
خود ربات (bot client). اگر `TELETHON_API_ID` و `TELETHON_API_HASH`
را ست نکنی، bot client کار نمی‌کند و ربات فایل بزرگ را در صورت
نیاز تیکه‌تیکه می‌کند (سقف ۱۰ قسمت).

### ۵٫۱ گرفتن API ID و API Hash

1. با مرورگر برو به https://my.telegram.org و با شماره تلگرامت وارد شو.
2. برو به **API development tools**.
3. یک اپ بساز (اسم و پلتفرم را هر چیزی بزن) و `api_id` و `api_hash`
   را کپی کن.
4. این دو مقدار را برای خودت نگه دار؛ `api_hash` مثل رمز است و
   نباید برای کسی بفرستی.

### ۵٫۲ ساختن StringSession با ترمینال

این اسکریپت کوتاه را روی کامپیوتر خودت اجرا کن (نه توی چت و نه
برای کسی نفرست):

```python
from telethon import TelegramClient
from telethon.sessions import StringSession

api_id = 12345678          # همان api_id خودت را بزن
api_hash = "xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx"  # همان api_hash خودت را بزن

with TelegramClient(StringSession(), api_id, api_hash) as client:
    print(client.session.save())
```

اولین بار شماره تلفنت را می‌خواهد و بعد کد ورود تلگرام را. در
آخر یک رشته طولانی چاپ می‌کند — همان StringSession است.

> ⚠️ این رشته، **ورود کامل به حساب تلگرامت** است؛ هر کسی آن را
> داشته باشد می‌تواند با حسابت وارد شود. آن را به هیچ‌کس نفرست،
> توی چت نفرست، توی فایل عمومی نگذار و فقط توی Variables ریل‌وی
> واردش کن.

### ۵٫۳ ساخت سشن با get_session.py (روی کامپیوتر)

فایل `get_session.py` توی همین ریپو است؛ دستور `/makesession`
حذف شده و سشن دیگر توی چت ساخته نمی‌شود:

1. فایل `get_session.py` را روی کامپیوتر خودت باز کن و دو خط اولش
   را با `api_id` و `api_hash` خودت پر کن.
2. اجرا کن: `python3 get_session.py`
3. شماره تلگرامت را بده، بعد کد ورود ۵ رقمی که تلگرام فرستاد را
   وارد کن (اگر رمز دومرحله‌ای خواست، آن را هم بده).
4. یک رشته طولانی چاپ می‌شود — همان StringSession است. آن را توی
   Variables ریل‌وی به اسم `TELETHON_SESSION_STRING` بگذار.

> ⚠️ این رشته، **ورود کامل به حساب تلگرامت** است؛ هر کسی آن را
> داشته باشد می‌تواند با حسابت وارد شود. آن را به هیچ‌کس نفرست،
> توی چت نفرست و توی فایل عمومی نگذار.

### ۵٫۴ وارد کردن متغیرها در Railway

توی سرویس، تب Variables، این سه مورد را اضافه کن (سشن را با
بخش ۵٫۳ می‌سازی):

- `TELETHON_API_ID` = همان api_id (عدد)
- `TELETHON_API_HASH` = همان api_hash
- `TELETHON_SESSION_STRING` = رشته‌ای که `get_session.py` چاپ کرد

بعد از ذخیره، سرویس دوباره دیپلوی می‌شود.

### ۵٫۵ نکته‌ها و هشدار مهم

- این سشن متعلق به یک **حساب کاربری** است، نه ربات. ربات با
  `BOT_TOKEN` کار می‌کند و لینک‌ها را می‌گیرد؛ ارسال با حساب
  کاربری فقط وقتی انجام می‌شود که `TELETHON_SEND_ENABLED=true`
  ست شده باشد، وگرنه همه ویدیوها فقط با خود ربات فرستاده می‌شوند.
- حساب کاربری Telethon باید عضو گروه باشد تا بتواند توی گروه
  فایل بفرستد؛ برای پی‌وی هم باید با گیرنده دیالوگ داشته باشد.
  اگر این‌طور نباشد، ارسال با Telethon ناموفق می‌شود و ربات
  خودکار برمی‌گردد به همان مسیر تیکه‌تیکه کردن.
- ⚠️ استفاده از حساب کاربری به‌جای ربات **خلاف قوانین تلگرام
  است** و حساب ممکن است محدود یا بن شود؛ دقیقاً مثل سلف‌بات.
  پس این بخش را با حسابت اصلی‌ات فعال نکن؛ اگر می‌خواهی، با یک
  حساب جداگانه که برایت مهم نیست این کار را بکن.
- اگر API ID/Hash ست نباشند یا سشن ساخته نشده باشد، ربات کاملاً
  بدون Telethon کار می‌کند و چیزی خراب نمی‌شود.

## ۶. اگر پورن‌هاب خطای 403 داد (اختیاری: کوکی)

**علت:** پورن‌هاب IP دیتاسنتر ریل‌وی را به‌عنوان ربات تشخیص می‌دهد
و درخواست دانلود را با `HTTP Error 403: Forbidden` رد می‌کند. خود
ربات خراب نیست و لینک هم لزوماً مشکل ندارد — از یک IP دیگر همان
لینک باز می‌شود.

**راه اول (خودکار، چیزی لازم نیست):** ربات حالا با impersonation
مرورگر کروم کار می‌کند — یعنی اثر انگشت TLS و هدرهایش شبیه کروم
واقعی است — و هر دانلود را تا ۵ بار تلاش می‌کند. برای فعال شدنش
فقط کافی است نسخه جدید دیپلوی شود؛ `curl-cffi` همراه
`requirements.txt` نصب می‌شود و به تنظیم اضافه نیاز ندارد. اگر با
همین راه درست شد، بقیه این بخش را لازم نداری.

**راه دوم (فقط اگر راه اول جواب نداد): کوکی‌های مرورگر.** با کوکی،
yt-dlp مثل مرورگر لاگین‌شده خودت عمل می‌کند و 403 را رد می‌کند:

1. توی مرورگر کامپیوتر/گوشی، توی پورن‌هاب لاگین کن.
2. افزونه **Get cookies.txt LOCALLY** (کروم یا فایرفاکس) را نصب کن،
   برو به صفحه pornhub.com و با افزونه خروجی `cookies.txt` بگیر.
   فقط کوکی‌های همان سایت را خروجی بگیر، نه همه سایت‌ها.
3. فایل `cookies.txt` را باز کن و کل متنش را کپی کن. بعد توی
   Railway، تب Variables، یک متغیر جدید بساز:
   - `PORNHUB_COOKIES` = همان متن کامل فایل `cookies.txt`
   بعد از ذخیره، سرویس دوباره دیپلوی می‌شود. راه دیگر: اگر به
   Volume ریل‌وی دسترسی داری، فایل را با نام `cookies.txt` توی
   مسیر `/data` بگذار؛ ربات خودش آن را پیدا می‌کند.
4. دوباره همان لینک را بفرست.

> ⚠️ کوکی یعنی **نشست لاگین‌شده حساب پورن‌هابت**؛ هر کسی آن را
> داشته باشد می‌تواند با آن حساب کار کند. آن را به هیچ‌کس نفرست،
> توی چت تلگرام نفرست، توی گیت‌هاب نگذار و فقط توی Variables
> ریل‌وی واردش کن. بهتر است با یک حساب جدا که برایت مهم نیست
> این کار را بکنی. کوکی‌ها مدتی بعد منقضی می‌شوند؛ اگر دوباره 403
> گرفتی، یک `cookies.txt` تازه بگیر و جایگزین کن.

نکته: 403 به IP بستگی دارد؛ ممکن است یک ویدیو با impersonation
درست شود و ویدیوی دیگر نه. اگر یک لینک نشد، اول لینک دیگری را
امتحان کن و بعد سراغ کوکی برو.

## ۷. اگر اینستاگرام دانلود نشد (اختیاری: کوکی)

اینستاگرام هم مثل پورن‌هاب، IP دیتاسنتر را خیلی وقت‌ها بدون لاگین
رد می‌کند یا درخواست را کند/قطع می‌کند. ربات با impersonation
مرورگر کروم کار می‌کند، ولی اگر باز هم نشد، کوکی لاگین‌شده
اینستاگرام را اضافه کن — دقیقاً مثل کوکی پورن‌هاب (بخش ۶):

1. توی مرورگر توی اینستاگرام لاگین کن.
2. با افزونه **Get cookies.txt LOCALLY** فقط کوکی‌های
   `instagram.com` را خروجی بگیر.
3. متن کامل `cookies.txt` را توی Railway، تب Variables، به‌عنوان
   متغیر جدید بگذار:
   - `INSTAGRAM_COOKIES` = همان متن کامل فایل `cookies.txt`
   راه دیگر: فایل را با نام `instagram_cookies.txt` توی مسیر
   `/data` بگذار؛ ربات خودش آن را پیدا می‌کند.

> ⚠️ کوکی یعنی **نشست لاگین‌شده حساب اینستاگرامت**؛ آن را به
> هیچ‌کس نفرست، توی چت تلگرام نفرست و توی گیت‌هاب نگذار. کوکی‌ها
> مدتی بعد منقضی می‌شوند؛ اگر دوباره دانلود نشد، یک `cookies.txt`
> تازه بگیر و جایگزین کن.

## نکته‌ها

- اینستا، تیک‌تاک و پورن‌هاب گاهی جلوی دانلود رو می‌گیرن؛ اگه
  یه لینک نشد، لینک دیگه رو امتحان کن. برای پورن‌هاب، اول
  impersonation (بخش ۶) را چک کن و فقط در صورت نیاز سراغ کوکی برو.
  یوتیوب با وب‌سرویس GFw می‌آید (کلید `GFWDEV_API_KEY` توی
  Variables ریل‌وی)؛ اگر وب‌سرویس خواب باشد، یوتیوب هم خواب است
  و fallback به yt-dlp ندارد. لینک‌های ویدیو حدود ۶ ساعت اعتبار
  دارند، پس دانلود باید همان‌موقع شروع شود. دانلود لینک‌های
  googlevideo با درخواست‌های Range موازی انجام می‌شود چون
  استریم ساده‌اش خفه می‌شود؛ اگر 403 خورد، لینک تازه یک بار
  گرفته می‌شود. اگر ربات برای یوتیوب
  گفت «کلید وب‌سرویس تنظیم نشده»، یعنی `GFWDEV_API_KEY` ست نشده؛
  اگر گفت «کلید مشکل داره»، یعنی کلید نامعتبر یا منقضی شده است.
- سقف ۵۰ مگابایت فقط برای Bot API از طریق HTTP است؛ فایل بزرگ
  را خود ربات با Telethon bot client تا ۲ گیگابایت می‌فرستد
  (بخش ۵). تقسیم فقط آخرین راه است و سقف ۱۰ قسمت دارد، پس
  ویدیوی خیلی طولانی به ده‌ها قسمت تبدیل نمی‌شود. ارسال با حساب
  کاربری فقط وقتی فعال است که `TELETHON_SEND_ENABLED=true` ست
  شده باشد (بخش ۵).
- اگه ربات توی گروه جواب نداد، اول Privacy Mode رو چک کن (بالا).
